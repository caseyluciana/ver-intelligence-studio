Section 1

Project Overview

Owner: Casey Luciana Candelaria-Logan, VER Team (Salesforce DET)  ·  Stack: Pure static HTML/CSS/JS — no build step, no framework  ·  Deployment: Google Apps Script or any static file host

The VER Intelligence Hub is a multi-page static web application built for the Salesforce DET Vendor Engagement & Reliability (VER) team. It serves as an FY27 command center for vendor intelligence, renewals, governance, TCO analysis, and team operations.

Audience Tiers

  • VER Team — team portal, trackers, CQBR generator, chief of staff
  • Internal Stakeholders — intel hub pages, exec snapshot, renewal horizon
  • Suppliers / Vendors — supplier portal (portal_*.html pages)
  • Other Tools — standalone tools (TCO calculator, CQBR Generator v2)

Important: VER serves stakeholders — surfacing intelligence, routing decisions, and delivering analysis so the business can act with confidence. VER does not process Change Orders (CO). Remove any CO Review, CO Generator, or CO metrics references if found on any page.

Key Architectural Rules

  • Every page is fully self-contained — all CSS and JS is inline within each HTML file
  • The assets/ folder is only used by main hub pages (page_*.html, index.html)
  • Portal, vendor, and tracker pages carry their own inline styles
  • No external JS frameworks — plain ES5 JavaScript throughout for broad compatibility
  • Google Fonts (Inter) loaded via CDN; all other assets are inline or from trusted CDNs
Section 3

Theme System

There are two separate theme systems depending on which page group you're editing.

Hub Pages (page_*.html, index.html)

Uses data-theme attribute on <html>:

document.documentElement.setAttribute('data-theme', 'dark' | 'light');
localStorage.setItem('ver-theme', theme);
// CSS switches via [data-theme="dark"] { ... } blocks

Portal & Team Pages (portal_*.html, team_portal.html, *_tracker.html)

Uses CSS classes on <body>:

document.body.classList.add('light-mode');   // light
document.body.classList.add('mid-mode');     // mid (default)
// neither class = dark mode
localStorage.setItem('ver-portal-theme', 'light' | 'mid' | 'dark');

Section 4

Navigation & Routing

Hub Navigation

Hub pages use data-nav attributes and are wired in assets/app.js. The sidebar uses <a href="page_name.html"> relative links.

Google Apps Script Link Rewriting

When deployed on Apps Script, all href="page_name.html" links are automatically rewritten to ?page=page_name by the IIFE at the bottom of each file. Do not remove this IIFE from any page — it is harmless when running locally.

(function(){
  var isAppsScript = window.location.href.indexOf('script.google.com') > -1
    || window.location.href.indexOf('googleusercontent.com') > -1;
  if(!isAppsScript) return;
  function rewriteLinks(){
    document.querySelectorAll('a[href]').forEach(function(a){
      var href = a.getAttribute('href');
      if(!href||href.startsWith('http')||href.startsWith('#')||!href.match(/\.html/)) return;
      var page = href.replace(/\.html.*$/,'').replace(/^.*\//,'');
      a.setAttribute('href', window.location.href.split('?')[0]+'?page='+page);
    });
  }
  document.readyState==='loading'
    ? document.addEventListener('DOMContentLoaded',rewriteLinks)
    : rewriteLinks();
  new MutationObserver(rewriteLinks).observe(document.body,{childList:true,subtree:true});
})();

Back Bars

Hub pages have a .back-bar at the top linking back to index.html. Standalone tools have this removed — see tco_standalone.html for the pattern.

Section 6

Key Tools Reference

6.1 TCO Calculator

Files: page_tco.html (hub version) · tco_standalone.html (standalone — no hub nav, no DET/VER references, all inputs start at $0)

Engagement types: Software/SaaS · SOW Engagement · Cloud & Infrastructure · Professional Services · Contingent Workforce · Mobility & Telecom

Modes: Decision Support (all inputs start at $0, benchmark insights active) | Audit & Review (enter actual costs for variance analysis)

Core Functions

  • buildCategories() — renders all input sliders for the selected engagement type
  • getCatTotal(catId) — calculates a category total (handles hrs/FTE/% special units)
  • get3YrTotal() — returns year-by-year array and total TCO across the full contract term (1–5 yrs or sub-year months for SOW)
  • updateTermUI() — updates term button highlights, ts-period label, donut-center-lbl, and shows/hides year KPI columns (Year 1–5) based on selected term
  • formatTermLabel() — returns human-readable term string e.g. "3-year", "6-month"
  • updateVERTip() — fires benchmark insight tip for the active engagement type; all 6 types have tips with smart input-value triggers
  • getHiddenCostPct() — calculates % of total TCO hidden beyond contracted value
  • openAssessModal() — generates the full TCO assessment report modal
  • exportPDF() — print-to-PDF via window.print() with .printing body class
  • exportCSVSummary() / exportCSVFull() — CSV download via Blob URL

Dynamic Term Labels

The running total strip (#ts-period), donut center label (#donut-center-lbl), and year KPI columns all update live when the term changes. Year 4 and Year 5 columns are hidden by default and revealed when a 4- or 5-year term is selected. Sub-year SOW terms (3 Mo, 6 Mo etc.) show a single period column labelled in months.

Internal Rate Constants

var INTERNAL_RATE = 200; // $ per hour for FTE/hours inputs
var HELPDESK_COST = 25;  // $ per support ticket

URL Pre-population

Hub links pass ?vendor=NAME&type=TYPE&spend=VALUE&mult=MULT query params. The loadFromURL() function reads these and pre-fills inputs.

6.2 CQBR Generator

Files: page_cqbr_generator.html (hub) · portal_cqbr_generator.html (team portal)

Generates Cognizant Quarterly Business Review documents from structured input. Produces a formatted report covering performance, spend, risks, and actions.

Critical — Script tag inside template literal: The _toggleTheme function and its init IIFE must be in a separate <script> block after the main one. If inside the main script block, the HTML parser terminates on any </script> found in a template literal string, causing raw JS to render as visible text at the bottom of the page.

</script>  <!-- close main script first -->
<script>
function _toggleTheme(){ ... }
(function(){ /* theme restore IIFE */ })();
</script>

6.3 Cinematic Generator v2

File: page_cinematic_generator_v2.html — Standalone tool, NOT wired to hub nav.

Generates cinematic full-screen animated HTML presentations for any meeting type: MBR, QBR, Team, Offsite, Exec. Output is a self-contained standalone HTML file. Separate from the CQBR Generator — this is for general meetings, not Cognizant-specific QBRs.

6.4 Chief of Staff Module

There are two separate implementations that must not be confused:

  1. Built-in daily briefing — embedded inside team_portal.html as an overlay modal, triggered via openCoS(). Auto-shows once per day on login. Data lives in COS_DATA within the file. Accessible from the team portal hero bar only.
  2. Standalone CoS (chief_of_staff.html) — separate personal executive assistant dashboard. NOT in the portal sidebar nav. Accessed directly via URL. Has its own independent data model.

Never merge these two. The embedded briefing is a lightweight daily digest for the team. The standalone CoS is a full personal tool. They are intentionally separate.

Sticky Header Heights

  • Top bar: 52px — use top: 52px for sticky elements below it
  • Running total strip (TCO): also 52px — use top: 104px when both are present

position:sticky Scoping Rule

Sticky only works relative to the nearest scrolling ancestor. A sticky element inside a flex child with overflow:hidden will not stick to the viewport. Ensure the containing div has overflow-y:auto.

Step 1 — Override semantic variables at root level

body.light-mode {
  --green: #059669;    /* replaces neon #34D399 */
  --amber: #B45309;    /* replaces neon #FBBF24 */
  --red:   #DC2626;    /* replaces bright #F43F5E */
}

Step 2 — Override component classes

/* Status pills */
body.light-mode .sp-green { background:rgba(5,150,105,0.14); color:#059669; border-color:rgba(5,150,105,0.35); }
body.light-mode .sp-amber { background:rgba(180,83,9,0.12);  color:#B45309; border-color:rgba(180,83,9,0.30); }
body.light-mode .sp-red   { background:rgba(192,20,60,0.12); color:#C0143C; border-color:rgba(192,20,60,0.30); }

/* Bar tracks */
body.light-mode .hbar-track { background: rgba(26,8,24,0.18) !important; }

var gridColor  = isLight ? 'rgba(26,8,24,0.15)' : 'rgba(255,255,255,0.15)';

Section 10

Known Quirks & Gotchas

Script Tag Inside Template Literal

Problem: The HTML parser terminates a <script> block when it encounters </script> — even inside a JS string or template literal.
Solution: Close the main script block before any function that produces </script> in a string, then open a new <script> block for those functions.

Emoji Splitting

Problem: '🐹🐻'.split('') produces question marks — multi-codepoint emoji split at the UTF-16 code unit level, not grapheme clusters.
Solution: Store emoji collections as arrays, not strings:

// Wrong — splits at UTF-16 boundaries, produces broken chars
var emojis = '🐹🐻'.split('');

// Correct — each emoji is already a discrete element
var emojis = ['🐹', '🐻'];

onerror HTML Injection

Problem: onerror="this.parentNode.innerHTML='<div>...'" breaks when the HTML string contains " — the browser parses it as closing the attribute.
Solution: Always use document.createElement() in onerror handlers (see Section 7).

Panel Height Bleeding

When a detail panel should match the viewport height (not page height), use:

.detail-panel {
  height: calc(100vh - 104px); /* 52px topbar + 52px toolbar */
  position: sticky;
  top: 0;
  align-self: flex-start;     /* NOT align-self: stretch */
}

align-self: stretch extends the panel to full page height, producing a white box below content in light mode.

Section 11

Google Apps Script Deployment

All pages include an IIFE that detects Apps Script hosting and rewrites .html links to ?page= query parameters. Do not remove this IIFE from any page.

(function(){
  var isAppsScript = window.location.href.indexOf('script.google.com') > -1
    || window.location.href.indexOf('googleusercontent.com') > -1;
  if(!isAppsScript) return;
  function rewriteLinks(){
    document.querySelectorAll('a[href]').forEach(function(a){
      var href = a.getAttribute('href');
      if(!href||href.startsWith('http')||href.startsWith('#')||!href.match(/\.html/)) return;
      var page = href.replace(/\.html.*$/,'').replace(/^.*\//,'');
      var base = window.location.href.split('?')[0];
      a.setAttribute('href', base+'?page='+page);
    });
  }
  if(document.readyState==='loading'){
    document.addEventListener('DOMContentLoaded',rewriteLinks);
  } else { rewriteLinks(); }
  new MutationObserver(rewriteLinks).observe(document.body,{childList:true,subtree:true});
})();

For the Apps Script host file, each ?page=NAME request resolves to NAME.html and its content is served.

Section 12

Maintenance Checklist

Adding a New Hub Page

  • Create page_newname.html based on an existing page as a template
  • Add the ← VER Intelligence Hub back bar at the top
  • Include the Apps Script link rewriter IIFE at the bottom of the <script> block
  • Add a nav link in index.html sidebar
  • Add entry to this guide's page index

Adding a New Portal Page

  • Create portal_newname.html
  • Include the three-mode theme system (_toggleTheme + restore IIFE)
  • Add light-mode overrides for all status pills, bar tracks, and color variables
  • Include the Apps Script link rewriter IIFE
  • Add sidebar link in team_portal.html if it is a team tool
  • Add entry to this guide's page index

Fixing Light-Mode Colors

  1. Check if the broken color uses a CSS variable (var(--amber) etc.)
  2. If yes → add the variable override to the body.light-mode { } block
  3. If no → add a specific body.light-mode .classname { } override

Updating Vendor Data

  • Hub vendor data: edit assets/data.js
  • Portal vendor data: search for VENDOR_DOMAINS and VENDORS arrays within each portal page
  • Preferred Tier 1 AMER vendors: Accenture, Cognizant, IBM, Infosys, TCS, Wipro, HCL, Capgemini, NTT Data, DXC, Deloitte, PwC, EY, KPMG, BCG, McKinsey

Adding a Team Member

Edit the TEAM_MEMBERS array in team_portal.html:

{ id: 'newid', name: 'Full Name', role: 'VER Role', emoji: '👤', color: '#HEX', director: false }

Deploying the Standalone TCO Calculator

Use tco_standalone.html — all hub nav, back links, and DET/VER references are removed. Safe to share with external teams or host in a Forge space. Key differences from page_tco.html:

  • All inputs start at $0 — no pre-populated benchmark defaults
  • All 6 engagement types have benchmark insight tips (Cloud & Infrastructure, Professional Services, Contingent Workforce, Mobility & Telecom each have 4 smart-trigger tips)
  • Term labels, donut centre, and year KPI columns (Year 1–5) update dynamically with term selection
  • Full calculation engine, AI augmentation panel, CSV/PDF export, and assessment report all work independently
  • No Portfolio TCO dashboard link and no hub footer branding
