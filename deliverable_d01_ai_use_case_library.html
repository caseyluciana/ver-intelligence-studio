📍 The problem it solves

Right now, knowledge about what works with AI in DA&O lives in individual contributors' heads. When someone wants to know whether a use case has been tried, there's no place to look. When a new initiative starts, there's no baseline — no "here's what we already know." That knowledge siloing slows everything down and guarantees we repeat mistakes we've already made.

The AI Use Case Library ends that. One structured catalog, maintained quarterly, that captures every use case we've touched — what we built, what it did, what it cost, and what we learned. And because it's structured, any team in DET can fork it for their own org.

🗂️ How use cases are classified

Every entry is assigned a status tier — so the library is honest about what's proven, what's in progress, and what we tried and learned from.

Live & Measured
In production, ROI documented, quarterly update in cycle.
Validated
Tested and proven — not yet in full production rollout.
In Development
Actively being built — design locked, build underway.
Proposed
Scoped and worth pursuing — not yet started.
Lessons Learned
Tried, not continued. Documented rationale on file — don't repeat, do reference.
🏗️ What each entry contains

Six fields per use case — enough to make a build or buy decision, assess risk, and measure value. No more, no less.

Use Case Name
Plain-language name + one-line description of what it does.
Pillar
VER Ops · Financial Intelligence · AI Ops · DA&O Strategy
Status
Tier classification with last-updated date.
AI Method / Tool
Claude, Gemini, GPT, Claude Code — what's doing the work and why.
Value Driver
Time saved · Cost avoided · Quality improved — quantified where measurable.
Outcome Summary
One sentence: what changed because this use case exists.
🔄 How it's maintained & extended

The library is refreshed quarterly alongside the DA&O AI Health Score (D04). New use cases enter as Proposed and graduate through tiers as they're built, tested, and measured. Entries that don't progress in two cycles get a Lessons Learned review.

Any team in DET can request a use case be added or request the library template for their own org. Requests route through AI Strategy & Ops — evaluated against the Build/Buy/Configure framework (D04 Component 02) before entering the backlog.

Adding a use case
Submit via the AI Strategy & Ops intake form — name, pillar, value hypothesis, and preferred status. Reviewed within one sprint.
Forking for your org
The library schema is portable. Any DET team can request the template and seed it with their own use cases — AI Strategy & Ops provides the framework and first-review.
